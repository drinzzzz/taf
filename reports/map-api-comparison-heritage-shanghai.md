# HERITAGE SHANGHAI 地图 API 方案对比分析

## 项目背景
- **项目名称**: HERITAGE SHANGHAI (hs.enth.org)
- **功能需求**: 外滩区域 30+ 建筑标记、步行路线绘制、卫星视图、历史地图叠加
- **目标用户**: 中国大陆用户（无 VPN）
- **技术栈**: Vue 3 + Element Plus
- **部署环境**: 上海服务器
- **预算偏好**: 免费/低成本

---

## 七种地图 API 方案详细对比

### 1. 高德地图 JS API 2.0

| 维度 | 详情 |
|------|------|
| **价格** | 个人开发者免费（日配额 30 万 -500 万次，视认证等级）；企业认证后配额更高；超出后约 ¥5-10/千次 |
| **中国可用性** | ⭐⭐⭐⭐⭐ 国内最佳，无需 VPN，CDN 全国覆盖 |
| **上海瓦片质量** | ⭐⭐⭐⭐⭐ 外滩区域精度极高，建筑轮廓清晰，POI 丰富 |
| **中文标签支持** | ⭐⭐⭐⭐⭐ 原生中文，地名标注完善 |
| **卫星视图** | ✅ 支持，更新频率较高（1-2 年） |
| **移动端性能** | ⭐⭐⭐⭐⭐ 针对国内网络优化，加载速度快 |
| **API Key 要求** | ✅ 需要注册开发者账号，创建 Key 并设置白名单 |
| **坐标系** | **GCJ-02**（火星坐标系）- 需注意与 WGS-84 转换 |
| **历史地图叠加** | ⚠️ 需自行实现 ImageOverlay，无内置历史地图 |
| **街景** | ✅ 支持（部分区域覆盖） |
| **其他特点** | 提供丰富的覆盖物 API（Marker、Polyline、Polygon），支持自定义样式 |

**代码示例**:
```javascript
import { AMapLoader } from '@amap/amap-jsapi-loader'
AMapLoader.load({
  key: '您的 key',
  version: '2.0',
  plugins: ['AMap.Scale', 'AMap.ToolBar']
}).then((AMap) => {
  const map = new AMap.Map('container', {
    zoom: 16,
    center: [121.490694, 31.239410] // 外滩坐标（GCJ-02）
  })
})
```

### 2. 百度地图 JS API 3.0

| 维度 | 详情 |
|------|------|
| **价格** | 个人免费（日配额 30 万次）；企业认证后提升；商用需授权 |
| **中国可用性** | ⭐⭐⭐⭐⭐ 国内优秀，无需 VPN |
| **上海瓦片质量** | ⭐⭐⭐⭐ 较好，但部分区域标注不如高德详细 |
| **中文标签支持** | ⭐⭐⭐⭐⭐ 原生中文 |
| **卫星视图** | ✅ 支持，更新频率一般 |
| **移动端性能** | ⭐⭐⭐⭐ 良好 |
| **API Key 要求** | ✅ 需要百度账号，创建 AK 并设置 referer 白名单 |
| **坐标系** | **BD-09**（百度坐标系）- 需二次转换（WGS-84 → GCJ-02 → BD-09） |
| **历史地图叠加** | ⚠️ 需自行实现，无内置功能 |
| **街景** | ✅ 支持（覆盖范围较广） |
| **其他特点** | 提供全景 API、路线规划、POI 搜索等丰富功能 |

**注意**: 百度坐标系转换较复杂，若数据源为 WGS-84 需两次转换。

### 3. 天地图 (Tianditu)

| 维度 | 详情 |
|------|------|
| **价格** | ⭐⭐⭐⭐⭐ **完全免费**（国家地理信息公共服务平台） |
| **中国可用性** | ⭐⭐⭐⭐⭐ 官方服务，国内稳定 |
| **上海瓦片质量** | ⭐⭐⭐ 一般，城市区域尚可，细节不如商业地图 |
| **中文标签支持** | ⭐⭐⭐⭐⭐ 标准中文标注 |
| **卫星视图** | ✅ 支持（矢量/影像/地形多种类型） |
| **移动端性能** | ⭐⭐⭐ 一般，CDN 覆盖不如商业地图 |
| **API Key 要求** | ✅ 需要注册账号获取 TK（Token） |
| **坐标系** | **CGCS2000**（接近 WGS-84，可直接使用） |
| **历史地图叠加** | ⚠️ 需自行实现 |
| **街景** | ❌ 不支持 |
| **其他特点** | 官方权威数据，适合政府/学术项目；但 UI 较传统 |

**瓦片 URL 示例**:
```
矢量：http://t0.tianditu.gov.cn/vec_c/wmts?tk=您的 token
影像：http://t0.tianditu.gov.cn/img_c/wmts?tk=您的 token
```

### 4. Leaflet + 免费瓦片 (OSM/CartoDB/高德自拼)

| 维度 | 详情 |
|------|------|
| **价格** | ⭐⭐⭐⭐⭐ **完全免费**（开源方案） |
| **中国可用性** | ⭐⭐ **OpenStreetMap 在中国大陆访问不稳定**（间歇性被墙） |
| **上海瓦片质量** | ⭐⭐⭐ OSM 依赖众包，外滩核心区较好，周边一般 |
| **中文标签支持** | ⭐⭐⭐ OSM 中文标签不完整 |
| **卫星视图** | ⚠️ 需使用 Esri/Sentinel 等第三方源（可能受限） |
| **移动端性能** | ⭐⭐⭐⭐ 轻量级库（~40KB），性能好 |
| **API Key 要求** | ❌ OSM 无需 Key；CartoDB 免费层无需 Key |
| **坐标系** | **WGS-84 / EPSG:3857**（标准 Web 墨卡托） |
| **历史地图叠加** | ✅ **优秀** - ImageOverlay 支持完善，适合历史地图叠加 |
| **街景** | ❌ 需集成第三方（如 Mapillary） |
| **其他特点** | 高度可定制，插件生态丰富；但需自建瓦片代理解决访问问题 |

**代码示例**:
```javascript
import L from 'leaflet'
const map = L.map('map').setView([31.239410, 121.490694], 16)

// CartoDB 浅色瓦片（当前使用）
L.tileLayer('https://{s}.basemaps.cartocdn.com/light_all/{z}/{x}/{y}{r}.png', {
  maxZoom: 19
}).addTo(map)

// 历史地图叠加
L.imageOverlay('historical-map-1930.jpg', bounds).addTo(map)
```

**⚠️ 关键问题**: OSM 在中国大陆访问不稳定，建议通过上海服务器做瓦片代理缓存。

### 5. MapLibre GL + 免费瓦片

| 维度 | 详情 |
|------|------|
| **价格** | ⭐⭐⭐⭐⭐ **完全免费**（Mapbox GL JS 开源分支） |
| **中国可用性** | ⭐⭐⭐ 库本身无限制，但瓦片源可能受限 |
| **上海瓦片质量** | ⭐⭐⭐ 取决于瓦片源选择 |
| **中文标签支持** | ⭐⭐⭐ 取决于样式配置 |
| **卫星视图** | ⚠️ 需配置卫星瓦片源 |
| **移动端性能** | ⭐⭐⭐⭐ WebGL 渲染，性能优秀（但包体积较大 ~200KB） |
| **API Key 要求** | ❌ 使用自建瓦片源无需 Key |
| **坐标系** | **WGS-84 / EPSG:3857** |
| **历史地图叠加** | ✅ 支持（通过自定义 source） |
| **街景** | ❌ 需自行集成 |
| **其他特点** | 矢量瓦片支持，样式高度可定制；学习曲线较陡 |

**代码示例**:
```javascript
import maplibregl from 'maplibre-gl'
const map = new maplibregl.Map({
  container: 'map',
  style: {
    version: 8,
    sources: {
      'osm': {
        type: 'raster',
        tiles: ['https://a.tile.openstreetmap.org/{z}/{x}/{y}.png'],
        tileSize: 256
      }
    },
    layers: [{id: 'osm', type: 'raster', source: 'osm'}]
  },
  center: [121.490694, 31.239410],
  zoom: 16
})
```

## 坐标系转换参考

```javascript
// WGS-84 → GCJ-02 (高德/谷歌中国)
function wgs2gcj(lng, lat) {
  // 使用开源转换库如 coordtransform
  return coordtransform.wgs84ToGcj02(lng, lat)
}

// GCJ-02 → BD-09 (百度)
function gcj2bd(lng, lat) {
  return coordtransform.gcj02ToBd09(lng, lat)
}

// 推荐库：https://github.com/wandergis/coordtransform
```

## 最终推荐

### 🏆 首选方案：高德地图 JS API 2.0

**推荐理由**:
1. **国内可用性最佳** - 无需担心访问问题，CDN 覆盖全国
2. **上海数据质量最高** - 外滩区域建筑标注详细，POI 丰富
3. **免费额度充足** - 个人开发者日配额 30 万 +，足够项目使用
4. **API 完善** - Marker、Polyline、Polygon 等覆盖物 API 成熟
5. **中文支持完美** - 原生中文标签，无需额外配置
6. **移动端优化** - 针对国内网络环境优化，加载速度快

**注意事项**:
- 需处理 GCJ-02 坐标系（若数据源为 WGS-84 需转换）
- 历史地图叠加需自行实现 ImageOverlay
- 需注册开发者账号并配置 Key 白名单

---

### 🥈 备选方案：Leaflet + 高德瓦片代理

**适用场景**: 若希望保持开源方案，同时解决访问问题

**实施方案**:
1. 在上海 DW 服务器部署瓦片代理（缓存高德/OSM 瓦片）
2. 前端使用 Leaflet 加载代理后的瓦片
3. 利用 Leaflet 优秀的 ImageOverlay 实现历史地图叠加

**优势**:
- 保持开源技术栈
- 历史地图叠加功能完善
- 服务器代理解决访问稳定性

**劣势**:
- 需维护瓦片缓存服务
- 增加服务器负载

---

### 🥉 混合方案：高德底图 + Leaflet 覆盖物

**实施方案**:
1. 使用高德地图作为底图（保证访问和质量）
2. 在高德地图上叠加自定义覆盖物（Marker、Polyline）
3. 历史地图使用高德的 `AMap.ImageLayer` 实现

**优势**: 兼顾底图质量和覆盖物灵活性

## 实施建议

### 针对 HERITAGE SHANGHAI 项目的具体建议:

1. **立即采用**: 高德地图 JS API 2.0
   ```bash
   npm install @amap/amap-jsapi-loader
   ```

2. **坐标系处理**: 若建筑数据为 WGS-84，集成 coordtransform 库转换

3. **历史地图叠加**: 使用 `AMap.ImageLayer` 或自定义 Overlay

4. **性能优化**:
   - 使用高德提供的 WebGL 版本（2.0 已支持）
   - 标记聚合（30+ 建筑建议开启）
   - 按需加载插件

5. **备案要求**: 高德 API 需在工信部备案后使用（项目域名需备案）
