## 二、优先级问题清单

### 🔴 P0：生产风险，需立即修复

| 编号 | 问题 | 风险描述 | 建议修复 |
|------|------|----------|----------|
| P0-1 | **ENTH单点故障** | ENTH宕机则所有服务不可用（包括DW上的应用） | 部署ENTH备用节点或直接将DW服务暴露 |
| P0-2 | **无健康检查** | 后端服务崩溃后Nginx仍转发流量，用户看到502 | 配置Nginx `upstream` + `health_check` |
| P0-3 | **ICP合规风险** | 使用IP绕过备案拦截，长期可能被封禁 | 完成ICP备案或迁移至境外全量部署 |
| P0-4 | **DW无外网出口** | 无法主动拉取更新、发送告警、回调webhook | 配置NAT网关或允许受限外网访问 |

### 🟠 P1：高优先级，影响稳定性

| 编号 | 问题 | 风险描述 | 建议修复 |
|------|------|----------|----------|
| P1-1 | **两级Nginx级联** | ENTH→DW→应用，增加延迟和故障点 | 简化为ENTH直连DW应用端口 |
| P1-2 | **路径改写复杂** | 多处`proxy_redirect`/`sub_filter`，易出错 | 统一使用子域名而非路径分隔 |
| P1-3 | **Console分拆两机** | 前后端/静态文件分布两机，部署耦合 | 合并到单机或明确分离职责 |
| P1-4 | **重复Nginx配置** | `0.default.conf`与域名conf内容重复 | 清理冗余配置，统一入口 |

### 🟡 P2：中优先级，影响运维效率

| 编号 | 问题 | 风险描述 | 建议修复 |
|------|------|----------|----------|
| P2-1 | **无监控告警** | 服务异常无法主动发现 | 部署Prometheus+Grafana+Alertmanager |
| P2-2 | **运维依赖SSH手动** | 部署/重启需人工操作，易出错 | 引入Ansible或简单CI/CD脚本 |
| P2-3 | **无日志集中收集** | 故障排查需登录多台服务器 | 部署ELK或Loki集中日志 |
| P2-4 | **跨机通信无加密** | HTTP明文传输，JSON数据可能敏感 | 配置SSH隧道或mTLS |

### 🟢 P3：低优先级，改进建议

| 编号 | 问题 | 建议 |
|------|------|------|
| P3-1 | 服务端口混乱 | 统一端口规划文档（8000/8700/8502/333等） |
| P3-2 | CLUES Pro待迁移 | 加速迁移至统一架构，减少Flask单体依赖 |
| P3-3 | 缺少文档 | 补充架构图和应急手册 |
| P3-4 | 无容量规划 | 评估当前负载，预留50%余量 |

### 3.2 简化Nginx层级

**当前问题**：ENTH Nginx → DW Nginx → 应用（三级）

**目标架构**：
- **方案A（推荐）**：ENTH Nginx直接代理到DW应用端口，移除DW Nginx
  ```nginx
  # ENTH Nginx
  location /pm/ {
      proxy_pass http://124.221.119.232:8000/;
      proxy_set_header Host $host;
  }
  location /bb/ {
      proxy_pass http://124.221.119.232:8700/;
      proxy_set_header Host $host;
  }
  ```
  
- **方案B（保留DW Nginx）**：DW Nginx仅做本地路由，ENTH透传Host
  ```nginx
  # ENTH Nginx
  location /pm/ {
      proxy_pass http://124.221.119.232/pm/;
      proxy_set_header Host $host;  # 保留原始Host
  }
  ```

### 3.3 增加健康检查和监控

#### 3.3.1 Nginx健康检查配置
```nginx
upstream pm_backend {
    server 124.221.119.232:8000 max_fails=3 fail_timeout=30s;
    keepalive 32;
}

location /pm/ {
    proxy_pass http://pm_backend/;
    proxy_connect_timeout 5s;
    proxy_read_timeout 30s;
}
```

#### 3.3.2 监控栈部署（DW服务器）
| 组件 | 端口 | 用途 |
|------|------|------|
| Prometheus | :9090 | 指标采集 |
| Grafana | :3000 | 可视化 |
| Node Exporter | :9100 | 系统指标 |
| Loki | :3100 | 日志聚合 |
| Alertmanager | :9093 | 告警路由 |

#### 3.3.3 关键告警规则
- 服务端口不可达（blackbox exporter）
- CPU/内存使用率 > 80%
- 磁盘使用率 > 85%
- Nginx 5xx错误率 > 1%
- 响应时间P95 > 2s

## 五、总结

当前架构在**功能可用性**层面可以运行，但在**生产稳定性**层面存在显著风险：

1. **单点故障**是最大隐患（ENTH宕机=全系统不可用）
2. **无监控告警**导致故障发现依赖用户反馈
3. **复杂的路由设计**增加了维护成本和出错概率
4. **ICP合规问题**可能带来政策性风险

建议优先解决P0级问题，再逐步优化架构。若业务规模增长，应考虑重构为云原生架构（Kubernetes + Service Mesh）。
