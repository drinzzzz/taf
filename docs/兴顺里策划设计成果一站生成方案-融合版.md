## 二、八大功能模块

### 模块 1：📋 策划设计方案书（Design Proposal Book）

**定位**：面向甲方的正式策划设计提案，为兴顺里量身定制

**输入**：项目 ID → 拉取项目信息 + 标准配置 + 设施清单 + 评估结果 + 空间数据

**输出**：结构化 PDF 文档，含七大章节：

| 章节 | 内容 | 数据来源 |
|------|------|---------|
| 封面 | 项目名称/代码/区位/阶段/日期 | Project 表 |
| 1. 项目概述 | 区位分析、规模、产品定位、设计范围 | Project + 手动补充 |
| 2. 人宠友好评估 | 总分卡、6板块雷达图、星级、必选项达标清单 | EvaluationEngine |
| 3. 设施配置方案 | 按板块分组，每项含名称/规格/数量/布点建议 | Facility 表 |
| 4. 空间规划建议 | 6类空间的宠物友好设计要点（建筑/通道/节点/绿地/道路/立面） | Space + Auto-place |
| 5. 改造优先级 | 设施×影响度×成本×可行性四象限（模块 3 输出） | 模块 3 |
| 6. 交叉评估 | 与 HT/MC 标准对比及补项建议（模块 4 输出） | 模块 4 |
| 7. 空间叙事 | "携宠游客的一天"体验故事线（模块 5 输出） | 模块 5 |

**技术路线**：
- 后端 `POST /api/projects/{id}/deliverables/proposal`
- Jinja2 模板渲染 → Markdown
- `markdown-to-pdf-cjk-emoji` skill → PDF（CJK 支持已验证）
- 输出到 Nutstore `01_CURR_PRJ/兴顺里/策划方案书/`

### 模块 2：📦 设施配置清单（Facility BOQ）

**定位**：面向施工方/采购的设备材料清单

**输出**：结构化 XLSX，含：

| 列 | 来源 | 说明 |
|----|------|------|
| 序号 | auto | — |
| 板块 | Facility.category | P1-P6 |
| 编号 | Facility.standard_item_id | 标准项ID |
| 设施名称 | Facility.name | — |
| 类型 | Facility.type | 必选项/加分项 |
| 建议品牌/规格 | Facility.spec | 2-3品牌用`/`分隔 |
| 数量 | Facility.quantity | — |
| 布点区域 | Facility.position ↦ Space | 映射到空间名称 |
| 参考单价 | Facility.price（可选） | — |
| 小计 | quantity × price | — |
| 备注 | Facility.notes | — |

**特色**：
- 按板块分组 + 自动小计行
- 遵循 memory 材料清单铁律（不强制标价格、品牌用 `/` 分隔）
- 可选：补充价格/供应商信息后重新导出
- 三阶段版本：NC 概念清单 / EI 深化清单 / CO 施工清单

**技术路线**：`GET /api/projects/{id}/deliverables/boq?format=xlsx` → openpyxl

### 模块 3：🗺️ 智能图纸引擎（Smart Drawing Engine）

**定位**：将 auto-place 升级为专业策划级图纸生成

**三阶段输出**：

#### 3a. 智能布点图（DXF）
- 从现有网格算法升级为**空间感知布点**
- 读取 Space 实体多边形 → 在空间边界内布点
- 冲突检测：同类设施最小间距、异类不重叠
- 用 ezdxf 在原始底图上添加 `TAF-FACILITY` 图层
- 每个设施：符号（圆/方块）+ 标注文字 + 指向线
- 输出 DXF 文件

#### 3b. 标注渲染图（PNG）
- 在原底图基础上叠加标注层：
  - 设施图标 + 编号
  - 评分色块（绿/黄/红对应 P1-P6 板块得分率）
  - 人宠动线箭头（入口 → 通道 → 节点 → 休息区 → 出口）
  - 区位分析文字标注
- 技术：后端用 Pillow/Cairo 渲染，或前端 Fabric.js + 服务端截图
- 输出高分辨率 PNG + 独立图例

#### 3c. 热力分析图（可选）
- 设施密度热力图：展示各板块设施在空间中的分布密度
- 服务半径分析：以每个设施为圆心绘制覆盖范围

**端点**：
- `POST /api/projects/{id}/deliverables/layout` → DXF
- `POST /api/projects/{id}/deliverables/annotated-map` → PNG

### 模块 4：📊 改造优先级矩阵（Priority Matrix）

**定位**：策划核心——讲清楚"先做什么、为什么"

**输入**：设施列表 + 评分 + 扩展字段（estimated_cost / impact_score / feasibility）

**计算逻辑**：

```
影响度 (Impact)     ← 设施 type（prerequisite > credit）+ 板块权重
成本 (Cost)         ← Facility.price 或手动估算
可行性 (Feasibility) ← status（installed=高 / confirmed=中 / selected=低）
```

**输出**：

| 优先级 | 设施 | 影响度 | 成本 | 可行性 | 建议阶段 | 理由 |
|--------|------|--------|------|--------|---------|------|
| 🔴 近期 | 低位饮水点 | 9/10 | 低 | 高 | NC | 必选项+低成本 |
| 🟡 中期 | 宠物友好标识系统 | 7/10 | 中 | 高 | EI | 加分项+影响面大 |
| 🟢 远期 | 智能宠物寄存柜 | 5/10 | 高 | 中 | CO | 加分项+需硬件 |

**输出格式**：
- XLSX 四象限矩阵表（含阶段规划建议）
- PNG 气泡图（x=成本, y=影响度, 气泡大小=板块权重）

**技术路线**：`GET /api/projects/{id}/deliverables/priority-matrix` → 计算 + openpyxl/matplotlib

---

### 模块 5：🏗️ 多标准交叉评估（Cross-Standard Evaluation）

**定位**：一套设施跑多套标准，找重叠 + 生成补项清单

**场景**：兴顺里是 OS（开放式街区），但实际可能混合 HT（酒店）、MC（商业）业态

**处理流程**：

```
设施列表（35项 OS）
  ├→ 用 OS 标准评估 → 100/100 ⭐5
  ├→ 用 HT 标准评估 → ？/100（找出缺失项）
  ├→ 用 MC 标准评估 → ？/100（找出缺失项）
  └→ 用 AP 标准评估 → ？/100（找出缺失项）
```

**输出**：

#### 5a. 设施共用矩阵

| 设施 | OS | HT | MC | AP | 覆盖标准数 |
|------|:--:|:--:|:--:|:--:|:----------:|
| 室外饮水点 | ✅ | ✅ | ✅ | — | 3 |
| 宠物粪便收集箱 | ✅ | ✅ | ✅ | ✅ | 4 |
| 壁挂饮水器 | — | ✅ | — | — | 1（HT专属） |
| … | | | | | |

#### 5b. 补项清单

| 若达到 HT 满分 | 需新增 | 影响范围 |
|---------------|--------|---------|
| HT-P2-03 壁挂饮水器 | +1 项 | P2 板块 +5% |
| HT-P4-07 宠物临时寄存区 | +1 项 | P4 板块 +8% |
| … | | |

#### 5c. 冲突避坑指南

| 冲突项 | 说明 | 建议 |
|--------|------|------|
| OS 要求低位饮水点 vs HT 要求壁挂式 | 两类饮水器安装高度不一致 | 商业界面用壁挂，街道界面用低位 |

**技术路线**：`POST /api/projects/{id}/deliverables/benchmark` → 并行 EvaluationEngine × N 标准

### 模块 6：✍️ 空间叙事引擎（Spatial Narrative Engine）

**定位**：把评估数据翻译成「人+宠的真实体验故事」，用于汇报 PPT 和甲方沟通

**生成逻辑**：

```
设施清单 + 空间布局 + 评分数据
        │
        ▼
   LLM 叙事生成（结构化 Prompt）
        │
        ▼
  "携宠游客的一天"故事线
```

**故事线模板**：

```
【场景 1：抵达】停车场/入口
  引用设施：P1-01 宠物临时停泊区、P6-04 宠物友好标识系统
  叙事：车主将车停入宠物友好车位，看到醒目的宠物友好街区标识…

【场景 2：漫步】主通道/商业界面
  引用设施：P2-01 宠物粪便收集箱、P4-03 宠物饮水点
  叙事：沿着宠物动线漫步，每隔 50 米设有粪便收集箱和饮水点…

【场景 3：休憩】绿地/节点广场
  引用设施：P3-01 宠物活动草坪、P5-01 宠物休息长凳
  叙事：在草坪区和其它宠物主人交流，长凳设有宠物拴扣…

【场景 4：社交】商业界面/立面区
  引用设施：P4-02 宠物友好商户标识、P6-01 宠物社交角
  叙事：携带宠物进入贴有友好标识的咖啡馆，户外座位区设有宠物社交角…

【场景 5：离场】出口
  引用设施：P6-02 宠物清洁站
  叙事：离场前在清洁站为宠物擦脚、补充饮水，扫码获取下次游玩推荐…
```

**输出**：
- Markdown 叙事文档
- 每段嵌入引用设施 ID 和评分，可追溯
- 可直接粘贴到 PPT/公众号文章

**技术路线**：`GET /api/projects/{id}/deliverables/narrative` → LLM 生成

### 模块 7：🎨 渲染提示词管线（Rendering Prompt Pipeline）

**定位**：为每个空间生成 AI 效果图提示词，支撑方案书配图

**输出**：每个空间类型 × 3 视角的 Midjourney/SD prompt

**模板**：
```
现代中式开放式街区 · {space_type}空间
人宠友好设计：{facility_list}
建筑风格：现代中式，暖色调灯光，下午阳光
场景：人们遛狗，猫咪在{facility_name}上休息
技术要求：建筑可视化，UE5渲染，8K --ar 16:9
```

可选：对接 ComfyUI MCP（已有 skill）自动化出图

### 模块 8：📦 成果打包器 + 版本管理（支撑模块）

**定位**：编排上述所有模块，一键生成完整交付物

**产物清单（config/product_catalog.json）**：

```json
{
  "OS": {
    "NC": [
      {"id": "proposal",      "name": "策划方案书",       "format": "pdf"},
      {"id": "boq",           "name": "设施配置清单",     "format": "xlsx"},
      {"id": "layout_dxf",    "name": "智能布点图",       "format": "dxf"},
      {"id": "annotated_map", "name": "标注渲染图",       "format": "png"},
      {"id": "priority",      "name": "改造优先级矩阵",   "format": "xlsx"},
      {"id": "benchmark",     "name": "多标准交叉评估",   "format": "pdf"},
      {"id": "narrative",     "name": "空间叙事脚本",     "format": "md"},
      {"id": "prompts",       "name": "渲染提示词",       "format": "md"}
    ]
  }
}
```

**打包流程**：
1. 读取 `product_catalog.json` → 确定该产品线+阶段的产物列表
2. 8 端点并行调用生成
3. 按目录结构组织 → 打包 ZIP
4. 上传坚果云 → PROPFIND 逐项复核（遵循产物清单铁律）
5. 写入 `deliverables` 表（版本快照）

**版本管理**：
- `deliverables` 表：id/project_id/phase/version/files(JSONB)/config_snapshot(JSONB)/generated_at
- `GET /api/projects/{id}/deliverables/history` → 版本列表
- `POST /api/projects/{id}/deliverables/diff?v1=1&v2=2` → 版本对比

**一键生成端点**：`POST /api/projects/{id}/deliverables/package`

## 八、决策点

| 议题 | 选项 | 建议 |
|------|------|------|
| Phase 1 范围 | 5 模块 vs 3 模块 | 5 模块（方案书+清单+交叉+矩阵+打包），一次性产出完整成果 |
| 前端入口 | 项目详情页按钮 vs 独立「成果」tab | 独立「📦 成果」tab，集中管理生成/下载/历史 |
| PDF 方案 | weasyprint vs markdown→pdf | markdown→pdf（已有 skill，CJK 验证） |
| 价格字段 | DB 已有 price 但未填充 | 规格用 spec JSONB，价格手动输入或默认留空 |
| 空间数据 | 目前无 Space 实体 | Phase 1 可跳过空间感知，Phase 2 再升级 |
