## 二、核心设计原则

1. **数据驱动**：所有成果从 DB 实时生成，单一事实源
2. **一键输出**：操作路径 ≤2 步（选项目 → 生成）
3. **格式专业**：PDF/PPTX/XLSX/DXF，匹配设计行业交付标准
4. **可定制**：模板化输出，不同产品线/阶段可切换模板
5. **版本可溯**：每次生成保留快照，支持历史回溯

---

## 三、七大功能模块

### 模块 A：策划设计方案书（Design Proposal Book）⭐ 最高优先级

**定位**：面向甲方的正式策划设计提案，整合 TAF 评估结果 + 设计说明

**输入**：项目 ID → 拉取项目信息 + 标准配置 + 设施清单 + 评估结果 + 空间数据

**输出**：一份结构化 PDF/Markdown 文档，包含：

| 章节 | 内容来源 | 说明 |
|------|---------|------|
| 封面 | 项目 name/code/location/client | 自动套用模板 |
| 项目概况 | Project 表 + 手动补充 | 区位、规模、产品定位 |
| 人宠友好标准评估 | EvaluationEngine | 总分卡、6板块雷达图、星级评级 |
| 设施配置方案 | Facility 表 | 按板块分组，每项含名称/规格/数量/布点建议 |
| 空间规划建议 | Space + Auto-place | 6类空间（建筑/通道/节点/道路/绿地/立面）的人宠友好设计要点 |
| 对标分析 | compare_standards | 与 HT/MC 等其他标准的差异分析 |
| 实施建议 | recommendations + 手动补充 | 优先级排序、投资估算框架 |
| 附录 | 标准全文 | 评估标准原文引用 |

**技术路线**：
- 后端新增 `POST /api/projects/{id}/proposal` → 渲染 Jinja2 模板 → 输出 Markdown
- Markdown → PDF 通过 `markdown-to-pdf-cjk-emoji` skill（已有，CJK 支持）
- 输出到 Nutstore `01_CURR_PRJ/兴顺里/策划方案书/`

**前端**：项目详情页新增「📄 生成方案书」按钮

---

### 模块 B：设施配置清单（Facility BOQ）

**定位**：面向施工方的设备材料清单，对接采购/预算

**输入**：设施列表 + 数量 + 规格 + 价格（可选）+ 供应商（可选）

**输出**：结构化 XLSX，含：

| 列 | 来源 |
|----|------|
| 序号 | auto |
| 板块 | Facility.category |
| 设施编号 | Facility.standard_item_id |
| 设施名称 | Facility.name |
| 类型（必选/加分） | Facility.type |
| 建议规格 | Facility.spec（JSONB，可配置品牌/材质/尺寸） |
| 数量 | Facility.quantity |
| 单价 | Facility.price（可选） |
| 小计 | quantity × price |
| 布点区域 | Facility.position → 映射空间名称 |
| 备注 | Facility.notes |

**特色功能**：
- 按板块自动分组 + 小计行
- 品牌推荐列（从 facility spec.brands 读取，多品牌用 `/` 分隔）
- 支持导出前补充价格/供应商信息
- 格式规范：遵循 memory 中「材料清单铁律」

**技术路线**：后端 `GET /api/projects/{id}/boq?format=xlsx` → openpyxl 生成

---

### 模块 C：智能空间布点图（Smart Layout Plan）

**定位**：将 auto-place 从「网格算法」升级为「真实空间布点」，输出 DWG/DXF/PDF

**当前状态**：auto-place 是固定网格（x=grid_x + col×step, y=grid_y + row×step），未关联实际空间

**升级方向**：

1. **空间感知布点**
   - 读取已识别的 Space 实体（来自 DXF 图层识别）
   - 将 placement_rules 中的 `space_types` 映射到实际空间多边形
   - 在空间边界内随机/网格布点，而非全局平面

2. **冲突检测**
   - 同类别设施最小间距约束
   - 不同类型设施不能重叠

3. **输出管线**
   - 读取原始 DXF 底图 → ezdxf 添加 TAF-FACILITY 图层
   - 在每个设施位置绘制符号（圆/方块/图标）+ 标注文字
   - 输出 `{YYYYMMDD}_{project_code}_layout.dxf`
   - 同时生成 PDF 预览图（方便非 CAD 用户查看）

4. **图例自动生成**
   - 右下角自动插入图例表：设施符号 → 名称

**前端**：底图工作台新增「🎯 智能布点」→ 展示结果 → 「📥 导出 DXF」

---

### 模块 D：多标准对标分析（Multi-Standard Benchmarking）

**定位**：一份报告同时评估项目在多个标准下的表现，辅助产品定位决策

**场景**：兴顺里是 OS，但甲方可能考虑 HT（酒店）+ OS（街区）混合业态 → 需要知道「如果套用 HT 标准，还需要增加哪些设施？」

**实现**：
- 后端 `POST /api/projects/{id}/benchmark` 接受 `target_codes: ["HT","MC","AP"]`
- 并行评估同一设施列表在不同标准下的得分
- 输出对比矩阵：

| 板块 | OS 得分 | HT 得分 | MC 得分 | 差异分析 |
|------|---------|---------|---------|----------|
| P1   | 100%    | 85%     | 90%     | OS→HT 缺壁挂饮水器… |
| …    |         |         |         |          |

- 自动生成「补项清单」：要达到某标准满分，需新增哪些设施

**输出格式**：HTML 报告 + PDF（复用模块 A 的 PDF 管线）

---

### 模块 E：设计效果图提示词管线（Rendering Prompt Pipeline）

**定位**：从设施配置自动生成 AI 效果图提示词（Midjourney / SD / ComfyUI）

**场景**：甲方需要看到每个空间的「人宠友好」效果图 → 策划方案书需要配图

**实现**：
- 按空间类型（building/channel/node/green/road/facade）+ 该空间内的设施列表 → 生成结构化 prompt
- Prompt 模板示例：

```
/imagine pet-friendly open-block {space_type}, featuring {facility_list},
modern Chinese architectural style, warm lighting, afternoon sunlight,
people walking dogs, cats resting on {facility_name}, architectural visualization,
unreal engine 5 render, 8K --ar 16:9 --style raw
```

- 每空间生成 2-3 个视角的 prompt
- 输出到 Nutstore `01_CURR_PRJ/兴顺里/AI渲染提示词/`
- 可选：对接 ComfyUI MCP（已有 skill）实现自动化出图

**前端**：项目详情页新增「🎨 生成渲染提示词」

---

### 模块 F：一键成果包（One-Click Deliverable Package）

**定位**：汇总所有模块输出，打包为标准化交付物

**实现**：
- 后端 `POST /api/projects/{id}/deliverables`
- 按阶段（NC/EI/CO）自动选择模板集
- 并行生成：
  - 策划方案书 PDF（模块 A）
  - 设施清单 XLSX（模块 B）
  - 布点图 DXF + PDF（模块 C）
  - 对标报告 PDF（模块 D，可选）
  - 渲染提示词 MD（模块 E，可选）
- 打包为 `{YYYYMMDD}_{project_code}_deliverables.zip`
- 上传到 Nutstore：`01_CURR_PRJ/{项目名}/成果包/{阶段}/`

**配置驱动**：定义 `deliverable_catalog.json`，描述每个产品线/阶段应生成哪些文件：

```json
{
  "OS": {
    "NC": ["proposal", "boq", "layout", "benchmark"],
    "EI": ["proposal", "boq", "layout_detailed"],
    "CO": ["boq_construction", "layout_construction"]
  }
}
```

---

### 模块 G：阶段成果版本管理（Phase Deliverable Versioning）

**定位**：记录每次成果生成的版本，支持历史回溯和变更对比

**实现**：
- 新增 `deliverables` 表：
  - `id`, `project_id`, `phase`, `version`, `files`(JSONB: [{name, path, md5, size}]), `generated_at`, `config_snapshot`(JSONB)

- 每次生成时：
  1. 自动递增版本号
  2. 保存当前 DB 快照（标准配置、设施列表）到 `config_snapshot`
  3. 所有输出文件上传 Nutstore + 记录到 `files`
  4. 前端「成果历史」tab：版本列表 + 下载 + 版本间设施变更 diff

- `POST /api/projects/{id}/deliverables/diff?v1=2&v2=3` → 两个版本间的设施增减/评分变化

## 八、总结

本方案将 TAF 从「评估工具」升级为「策划设计成果生成平台」，核心思路是：

> **结构化数据 (DB) → 模板渲染 (Jinja2/openpyxl/ezdxf) → 专业格式输出 (PDF/XLSX/DXF) → 自动归档 (Nutstore)**

所有模块均为只读生成，不影响现有评估引擎。Phase 1 四模块可在 1-2 天内完成，立即为兴顺里产出一套完整的策划设计成果文件。
