# TAF 布点系统重构规划 v1 (2026-09-02)

## 一、问题诊断（用户反馈 → 根因）

| # | 反馈 | 根因 |
|---|------|------|
| 1 | 落位后无法拖动微调/无法删除单 marker | place 模式下 mouse:down 一律走 placeAtPointer（含点到已有 marker 时），拖动被吞; marker 无单选删除 |
| 2 | 落位后自动跳下一标准项 | 数据模型一标准项一 position, 默认"一个点就完事" → 架构错误 |
| 3 | 图标语义重复丑陋（点位库/仅可布点/手动布点同 📍）| 三个概念共用图标 |
| 4 | 自动布点描述需三行 (35/19/排除类目) | 文案未按用户规格 |
| 5 | "在左侧点位库切换分类"文案错 | 点位库在右2, 文案说左侧 |
| 6 | 间距/留白/数量每标准项要求不同; 自动布点应按标准项而非分类/全量 | 引擎只有全局 spacing/margin/perRow + 分类桶, 无标准项级规则 |

## 二、架构根因: 一标准项多实例缺失

`facilities` 表: 1 行 = 1 标准项 + quantity 字段 + **单一 position**
→ 无法表达"饮水点 4 处""路灯 12 盏"

### 方案 A: placements 独立表 (推荐)
```
facility_placements: id | facility_id(FK) | seq(1..n) | position JSONB | created_at
```
- facilities 保持评估模型不动（35 项计分不变）
- 布点实例独立 CRUD: 逐点拖动/删除/undo
- DXF 导出按 facility→placements 生成多 INSERT
- 后端新 router: GET/POST/DELETE /placements?facility_id=
- 一键清除 = DELETE WHERE facility_id; 拖单点 = PUT position

### 方案 B: position 改 JSONB 数组 (设施行内多坐标)
- 优点: 改动小
- 缺点: 评估/导出处 position 语义全变, 迁移风险大, JSONB 数组内更新并发竞态
→ 推荐 A。

## 三、交互细化

### 手动布点模式 (画布)
1. 点位库**选择标准项**（不是 facility 行= 标准项行）→ 工具栏「✍️ 手动布点」亮起
2. 画布点击一次 → 该标准项**新增一个实例 marker**（自动递增 seq）
3. **不自动跳转**——连续点击连续加点; 切换标准项在点位库点另一项
4. 点已有 marker → 进入拖动微调（place 分支排除 target 是 marker 的情况）
5. 选中 marker → Delete/Backspace 删除该实例; 点位库行 🗑 = 清该项全部实例
6. 双击点位库行 = 定位到该项第一点

### 自动布点 (按标准项)
- 点位库每标准项行右侧加「⚡ 自动布点」按钮 → 为该标准项生成 N 点（N 按该项默认规则）
- 不再提供"分类/全量自动布点"（无实战意义, 用户论断）
- 布点规则表驱动 (见下), 生成后仍可手动逐点微调

## 七、分步实施
1. **P0 数据层**: 建 facility_placements 表 + 迁移种子 (35 项现有 position 迁为 seq1)
2. **P0 后端**: placements CRUD API + DXF 导出改造 (多 INSERT)
3. **P1 前端手动**: place 模式多实例 + 不跳转 + 拖动修复 + 单点删除/清空
4. **P1 前端图标/文案**: 三图标语义 + 描述三行 + 左右文案修正
5. **P2 规则引擎**: PLACEMENT_RULES 表 (19 项默认) + 按项生成算法 (沿用几何锚点)
6. **P2 UI**: 点位库行级「⚡ 自动布点」+ 规则参数按项可调(±%)
7. **P3 验证**: DXF 全链路 (每项多层多实例) + CAD 复核
